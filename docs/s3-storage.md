# Медиа в Cloud.ru Object Storage

Вложения, аватары, голосовые сообщения, стикеры, превью и аудиокэш рингтонов хранятся в закрытом S3-бакете. Адреса `/uploads/...` и `/api/ringtones/audio` сохраняются: сервер читает S3 потоком и поддерживает HEAD, ETag и Range. Ключи доступа никогда не отправляются браузеру. Статические ресурсы интерфейса из `public/` остаются частью сборки.

## Настройка

Создайте в корне приложения `.s3-storage.json` (исключён из Git), права на сервере `chmod 600 .s3-storage.json`:

```json
{
  "endpoint": "https://s3.cloud.ru",
  "region": "ru-central-1",
  "bucket": "YOUR_BUCKET",
  "accessKeyId": "TENANT_ID:KEY_ID",
  "secretAccessKey": "KEY_SECRET"
}
```

Наличие файла включает S3. Альтернатива: `MEDIA_STORAGE=s3`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`. Можно задать `S3_CONFIG_FILE`, необязательный `S3_PREFIX` и `S3_LOCAL_ADDRESS` для привязки исходящих S3-соединений к физическому интерфейсу при VPN. Для локальной разработки без S3 конфигурация не требуется; принудительный локальный режим — `MEDIA_STORAGE=local`.

[Cloud.ru: настройка API](https://cloud.ru/docs/s3e/ug/topics/api__getting-started) требует логин в формате `tenant_id:key_id`. Используется path-style S3 API и приватный бакет, публичные ACL не нужны.

## Перенос существующих файлов

Перед включением S3 в рабочем приложении запустите миграцию с отдельной конфигурацией:

```sh
S3_CONFIG_FILE=/secure/path/s3-storage.json npx tsx scripts/migrate-media-s3.ts
S3_CONFIG_FILE=/secure/path/s3-storage.json npx tsx scripts/migrate-media-s3.ts --verify-only
```

Скрипт читает `uploads/` (включая `thumbs/`) и `data/ringtones/audio/`, сохраняет ключи `uploads/...` и `ringtones/audio/...`. `MEDIA_SOURCE_DIR` позволяет читать из другого каталога. Каждый объект скачивается обратно и проверяется по SHA-256 и размеру. Повторный запуск пропускает уже скопированные объекты, но повторно проверяет их. Конфликтующие объекты не перезаписываются; исходные файлы не удаляются. Перед переключением остановите приём новых загрузок и повторите миграцию, чтобы учесть файлы, появившиеся во время копирования. После успешного полного прохода для короткого финального переключения можно использовать `--skip-verified-downloads`: неизменившиеся файлы проверяются по локальному SHA-256 и метаданным S3, новые файлы по-прежнему скачиваются для полной проверки.

После проверки разместите конфигурацию в корне приложения и перезапустите PM2. Старые файлы можно оставить как резервную копию или переместить в отдельный архив. Новые загрузки удаляются с диска после записи и проверки S3; видео остаётся временно до окончания перекодирования и повторной записи. Ошибка обновления видео оставляет локальную копию для восстановления. Транскрибация и генерация превью используют временные файлы в `data/media-tmp/`, которые удаляются после обработки.

Автоматическое удаление объектов S3 не включено: удаление требует полного учёта ссылок, включая групповые аватары и наборы стикеров. Старый локальный сборщик также отключается в S3-режиме, чтобы сохранить резервные копии. JSON-данные чатов, пользователей, владельцев загрузок и ключ подписи URL остаются в `data/` и требуют обычного резервного копирования.

Откат требует сначала вернуть новые объекты S3 в соответствующие локальные каталоги, затем включить `MEDIA_STORAGE=local` и перезапустить сервер. Одного выключения S3 недостаточно, если после переключения были новые загрузки.
